# Конфигурация

[← К оглавлению](README.md) · [English](../en/configuration.md) · [中文](../zh/configuration.md)

---

Ravix читает конфигурацию из двух мест:

| Файл | Роль |
| --- | --- |
| `/etc/ravix/ravix.env` | **Настройки рантайма и сгенерированные учётные данные.** Пишется установщиком, подключается systemd-юнитом через `EnvironmentFile=`. Именно этот файл вы правите на сервере. |
| `backend/src/main/resources/application.properties` | **Значения по умолчанию, вшитые в сборку.** Каждое читает переменную окружения с фолбэком, так что обычно вы переопределяете, а не правите этот файл. |

После изменения любого из них:

```bash
sudo systemctl restart ravix
```

## Переменные окружения

### Сеть

| Переменная | По умолчанию | Примечание |
| --- | --- | --- |
| `RAVIX_HTTP_PORT` | `8080` | HTTP-порт бэкенда. Nginx проксирует сюда `/api/`. |
| `RAVIX_HTTP_HOST` | `127.0.0.1` | Адрес привязки. **Оставьте на loopback** — панель рассчитана на работу за Nginx. Ставьте `0.0.0.0`, только если осознанно выставляете API наружу. |
| `RAVIX_PANEL_PORT` | `9162` | Публичный HTTPS-порт, на котором Nginx отдаёт панель. Намеренно не 443, чтобы рядом мог жить вебмейл или сайт. |

### База данных

| Переменная | По умолчанию | Примечание |
| --- | --- | --- |
| `RAVIX_DB_URL` | `jdbc:postgresql://localhost:54322/postgres` | Установщик переписывает на базу `ravix` на порту 5432. |
| `RAVIX_DB_USER` | `postgres` | Установщик ставит `ravix`. |
| `RAVIX_DB_PASSWORD` | *(пусто)* | Установщик генерирует случайный пароль. Пустое значение осмысленно только для локальной dev-базы с trust-авторизацией. |

Ravix держит всё в отдельной схеме `ravix`. Flyway накатывает миграции из
`db/migration` при старте (`quarkus.flyway.migrate-at-start=true`), а Hibernate
только *валидирует* результат — то есть схемой владеют миграции, а не сущности.

### Учётная запись администратора

| Переменная | По умолчанию | Примечание |
| --- | --- | --- |
| `RAVIX_ADMIN_EMAIL` | `admin@example.com` | Создаётся **только если админов ещё нет**. Установщик ставит `admin@localhost`. |
| `RAVIX_ADMIN_PASSWORD` | *(пусто → генерируется)* | Оставьте пустым — Ravix создаст случайный пароль из 20 символов и напечатает его **один раз** при старте. Установщик задаёт его явно. |

> Дефолтного пароля намеренно **нет**: пароль по умолчанию — это опубликованный
> пароль. Если разворачиваете руками или в контейнере без env-файла, смотрите
> лог старта: сгенерированный пароль есть только там. Пропустили?
> `sudo ravixctl reset-admin <email> <пароль>`.

Потеряли пароль? `sudo ravixctl reset-admin <email> <пароль>`.

### Пути

| Переменная | По умолчанию |
| --- | --- |
| `RAVIX_PATH_CONFIG` | `/etc/ravix` |
| `RAVIX_PATH_DATA` | `/var/lib/ravix` |
| `RAVIX_DMARC_INBOX` | `/var/lib/ravix/dmarc/inbox` |
| `RAVIX_FBL_INBOX` | `/var/lib/ravix/fbl/inbox` |

Файлы, положенные во входящие каталоги DMARC и FBL, обрабатываются автоматически
— см. [DNS и доставляемость](dns-deliverability.md).

### Источники логов

Ravix читает эти файлы для страницы **Логи**. Переопределите, если в вашем
дистрибутиве они лежат иначе.

| Переменная | По умолчанию |
| --- | --- |
| `RAVIX_LOG_POSTFIX` | `/var/log/mail.log` |
| `RAVIX_LOG_DOVECOT` | `/var/log/mail.log` |
| `RAVIX_LOG_RSPAMD` | `/var/log/rspamd/rspamd.log` |
| `RAVIX_LOG_NGINX` | `/var/log/nginx/access.log` |
| `RAVIX_LOG_RAVIX` | `/var/log/ravix/ravix.log` |

### Цели провижининга почтового стека

Куда Ravix пишет сгенерированные конфиги. Меняйте, только если ваш почтовый стек
лежит нестандартно.

| Переменная | По умолчанию |
| --- | --- |
| `RAVIX_POSTFIX_DIR` | `/etc/postfix/ravix` |
| `RAVIX_DOVECOT_USERFILE` | `/etc/dovecot/ravix-users` |
| `RAVIX_DKIM_DIR` | `/etc/opendkim` |
| `RAVIX_RSPAMD_DIR` | `/etc/rspamd/local.d` |
| `RAVIX_VMAIL_BASE` | `/var/vmail` |
| `RAVIX_VMAIL_UID` | `5000` |
| `RAVIX_VMAIL_GID` | `5000` |

Ravix пишет в свои подкаталоги `ravix/` и оверрайды `local.d/`, а не заменяет
основные конфиги — поэтому написанные вручную настройки переживают применение.
См. [Почтовый стек](mail-stack.md).

### Только для установщика

Влияют на установку, в рантайме не читаются.

| Переменная | По умолчанию | Действие |
| --- | --- | --- |
| `RAVIX_DOMAIN` | – | Имя хоста панели. Задайте, чтобы запросить сертификат Let's Encrypt. |
| `RAVIX_TLS_EMAIL` | – | Контактный адрес для Let's Encrypt. |
| `RAVIX_FIREWALL` | `1` | Настроить UFW и fail2ban. `0` — пропустить. |
| `RAVIX_INSTALL_MODE` | `auto` | `auto` / `release` / `source`. |
| `RAVIX_VERSION` | `latest` | Тег релиза. |
| `RAVIX_REPO` | URL на GitHub | Репозиторий-источник (форк или зеркало Gitea). |
| `RAVIX_BRANCH` | `main` | Ветка для сборки из исходников. |
| `RAVIX_RELEASE_TOKEN` | – | Токен для приватных артефактов релиза. |
| `RAVIX_REINSTALL` | `0` | Только для source-установщика: перезаписать существующую установку. |

### Аутентификация и CORS

| Переменная | По умолчанию | Примечание |
| --- | --- | --- |
| `RAVIX_AUTH_MAX_FAILURES` | `5` | Неудачных входов на **имя пользователя** за окно до блокировки. |
| `RAVIX_AUTH_MAX_FAILURES_PER_IP` | `20` | Неудачных входов на **IP**. Намеренно выше: администраторы часто сидят за одним офисным IP, и жёсткий лимит позволил бы одному опечатавшемуся заблокировать всех. |
| `RAVIX_AUTH_WINDOW_SECONDS` | `300` | Скользящее окно, в котором считаются неудачи. |
| `RAVIX_AUTH_LOCKOUT_SECONDS` | `900` | Сколько держится блокировка. Ответ — `429` с `Retry-After`. |
| `RAVIX_CORS_ORIGINS` | dev-сервер Vite | Дополнительные origin, которым разрешён **кросс-доменный** вызов API. Same-origin разрешён всегда, поэтому обычной установке здесь ничего не нужно. |
| `RAVIX_QUEUE_MAX_ITEMS` | `500` | Ограничение на число элементов очереди в одном ответе. Сводные счётчики по-прежнему охватывают всю очередь. |

## Усиление дефолтов

Значения по умолчанию уже безопасны для типичного случая: панель на том же
origin, сессии в cookie, лимит попыток входа, отсутствие встроенного пароля
администратора. Остаётся в основном убавить шум. Переопределяйте в
`/etc/ravix/application.properties` — Quarkus читает этот файл из рабочего
каталога при старте:

```properties
# Убавить многословность лога в проде
quarkus.log.category."sh.ravix".level=INFO
```

Отдаёте фронтенд с другого хоста, чем API? Тогда — и только тогда:

```bash
RAVIX_CORS_ORIGINS=https://panel.example.com
```

Оставшиеся известные слабые места — в [Безопасности](security.md).

## Порты

| Порт | Сервис | Доступ |
| --- | --- | --- |
| `9162` | Панель Ravix (HTTPS через Nginx) | **Ограничьте своими IP.** |
| `8080` | API бэкенда | Только loopback. |
| `5432` | PostgreSQL | Только loopback. |
| `80`, `443` | Nginx / ACME | Публично. |
| `25` | SMTP | Публично — от него зависят входящая почта и ACME. |
| `465`, `587` | Submission | Публично. |
| `993`, `995`, `143`, `110` | IMAP / POP3 | Публично. |

При `RAVIX_FIREWALL=1` установщик открывает всё это в UFW. Порт панели
**не обязан** быть доступен всему миру — сужение доступа к нему даёт самый
большой прирост безопасности при наименьших усилиях.

## Проверка изменений

```bash
sudo systemctl restart ravix
sudo ravixctl doctor      # сервис, API, база, nginx
sudo ravixctl logs 100
```
