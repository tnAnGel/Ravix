## Требования

| | Минимум | Рекомендуемый VPS |
| --- | ---: | ---: |
| CPU | 1 vCPU | 2 vCPU |
| RAM | 2 ГБ | 4 ГБ |
| Диск | 10 ГБ SSD | 80+ ГБ SSD |

Диск расходуется в основном на хранение почты и бэкапы, а не на саму Ravix.

**ОС.** Основная цель — Debian 12 (bookworm); Ubuntu 22.04/24.04 LTS работает на
той же модели `apt` + `systemd`. Поддерживаются `amd64` и `arm64`. Без
`apt-get` установщик откажется работать.

**До начала:**

- **Чистый хост.** Ravix перезаписывает конфиги Nginx, PostgreSQL и почтового
  стека. Не ставьте её рядом с уже работающим почтовиком или важным веб-приложением.
- **Root-доступ.** Нужен и установщику, и самой панели.
- **Открытый исходящий 25-й порт.** Практически все облачные провайдеры (AWS,
  GCP, Azure, Oracle, DigitalOcean, Hetzner) блокируют его по умолчанию и
  открывают по тикету. Без него почту можно принимать, но не отправлять.
- **Статический IP с PTR-записью**, которой вы управляете. Почту с IP без
  обратной зоны почти все крупные провайдеры отклоняют или кладут в спам.
- **Доступ к DNS** всех доменов, которые собираетесь обслуживать.

## Быстрая установка

```bash
curl -fsSL https://raw.githubusercontent.com/tnAnGel/Ravix/main/install.sh | sudo bash
```

Или из клона:

```bash
git clone https://github.com/tnAnGel/Ravix.git
cd Ravix
sudo ./install.sh
```

С доменом — чтобы панель сразу получила сертификат Let's Encrypt:

```bash
RAVIX_DOMAIN=panel.example.com RAVIX_TLS_EMAIL=you@example.com sudo ./install.sh
```

В конце установщик печатает URL панели и сгенерированные учётные данные
администратора. **Запишите пароль** — он показывается один раз (и сохраняется в
`/etc/ravix/ravix.env`).

## Что делает установщик

1. Ставит рантайм-пакеты: PostgreSQL, Nginx, JRE Java 21 (с откатом на
   репозиторий Adoptium Temurin, если `openjdk-21-jre-headless` недоступен),
   плюс `curl`, `openssl`, `tar`.
2. Создаёт системного пользователя `ravix` и структуру каталогов (ниже).
3. Создаёт роль и базу PostgreSQL — обе называются `ravix` — со случайно
   сгенерированным паролем, записанным в `/etc/ravix/ravix.env`.
4. Скачивает готовые артефакты бэкенда и фронтенда последнего релиза,
   **сверяет их с `SHA256SUMS`** и отказывается ставить при несовпадении.
5. Пишет systemd-юнит и запускает сервис `ravix`.
6. Настраивает Nginx как обратный прокси: статика на `/`, бэкенд на `/api/`.
7. Если задан `RAVIX_DOMAIN` — запрашивает сертификат через Certbot.
8. Если `RAVIX_FIREWALL=1` (по умолчанию) — открывает почтовые порты и порт
   панели в UFW и включает fail2ban.

Сама Ravix установлена. **Почтовый стек — нет.** Postfix, Dovecot, Rspamd и
OpenDKIM ставятся потом из панели, в разделе **Платформа → Установка ПО**. См.
[Почтовый стек](mail-stack.md).

## Режимы установки

`install.sh` — быстрый путь: скачивает артефакты, единожды собранные в CI, так
что холодная установка занимает ~30–60 с вместо ~5–8 минут сборки из исходников.
Если релиз не опубликован (или вы попросили явно) — прозрачно откатывается на
сборку из исходников через `install-from-source.sh`.

| Переменная | По умолчанию | Действие |
| --- | --- | --- |
| `RAVIX_INSTALL_MODE` | `auto` | `auto` — релиз, если есть, иначе исходники. `release` — упасть, если релиза нет. `source` — всегда собирать. |
| `RAVIX_VERSION` | `latest` | Тег релиза, например `v0.1.0`. |
| `RAVIX_RELEASE_TOKEN` | – | Токен доступа; нужен только для артефактов из **приватного** форка. |
| `RAVIX_REPO` | URL репозитория на GitHub | Репозиторий-источник. Можно указать форк или self-hosted зеркало Gitea — установщик сам определит нужный API по хосту. |
| `RAVIX_BRANCH` | `main` | Ветка для сборки из исходников. |

```bash
# Принудительная сборка из исходников
RAVIX_INSTALL_MODE=source sudo ./install.sh

# Зафиксировать конкретную версию
RAVIX_VERSION=v0.1.0 sudo ./install.sh
```

Сборка из исходников дополнительно ставит Maven, JDK и Node.js и компилирует
Quarkus и бандл Vite прямо на хосте — заложите ~2 ГБ диска и несколько минут.

Порты, учётные данные и пути, которые можно переопределить при установке, — в
[Конфигурации](configuration.md).

## Структура установки

| Путь | Назначение |
| --- | --- |
| `/opt/ravix` | Рантайм бэкенда (`quarkus-app/`). |
| `/opt/ravix/src` | Чекаут исходников — только в режиме source; нужен для `ravixctl update`. |
| `/var/www/ravix` | Статика фронтенда, отдаётся Nginx. |
| `/etc/ravix/ravix.env` | Настройки рантайма и сгенерированные учётные данные. |
| `/var/lib/ravix` | Данные, входящие каталоги DMARC/FBL, бэкапы. |
| `/var/log/ravix` | Логи приложения. |
| `/usr/local/bin/ravixctl` | [CLI](cli.md). |

## Первый вход

1. Откройте URL, который напечатал установщик — `https://panel.example.com/`
   или `https://<ip>:9162/`.
2. Войдите со сгенерированными учётными данными.
3. **Сразу смените пароль** и включите 2FA в **Настройки → Безопасность**.
4. Пройдите [чеклист по усилению](security.md#чеклист-по-усилению).
5. Установите почтовый стек: [Почтовый стек](mail-stack.md).

Панель по умолчанию слушает порт `9162`, а не 443 — чтобы не конфликтовать с
вебмейлом или сайтом на том же хосте.

## Обновление

Из релиза:

```bash
curl -fsSL https://raw.githubusercontent.com/tnAnGel/Ravix/main/install.sh | sudo bash
```

Повторный запуск установщика заменяет бэкенд и фронтенд, сохраняет базу и
`/etc/ravix/ravix.env`, а Flyway накатывает миграции при следующем старте.

Из чекаута исходников:

```bash
sudo ravixctl update    # git pull, пересборка, деплой, рестарт
```

`ravixctl update` прерывается **до** того, как тронет рабочую установку, если
сборка упала — см. [CLI](cli.md#update).

Всегда сначала делайте бэкап:

```bash
sudo ravixctl backup
```

## Удаление

Скрипта удаления нет намеренно — панель делит хост с живым почтовым стеком,
поэтому снос делается руками.

```bash
sudo systemctl disable --now ravix
sudo rm -f /etc/systemd/system/ravix.service && sudo systemctl daemon-reload
sudo rm -rf /opt/ravix /var/www/ravix /var/log/ravix
sudo rm -f /etc/nginx/sites-enabled/ravix /etc/nginx/sites-available/ravix
sudo systemctl reload nginx
sudo -u postgres dropdb ravix && sudo -u postgres dropuser ravix
sudo rm -f /usr/local/bin/ravixctl
```

В `/var/lib/ravix` лежат бэкапы и входящие каталоги — просмотрите перед
удалением. Postfix, Dovecot, Rspamd и почта в `/var/vmail` останутся на месте;
убирайте их отдельно, если хотите снести и почтовый сервер.
