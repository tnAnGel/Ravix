# REST API

[← К оглавлению](README.md) · [English](../en/api.md) · [中文](../zh/api.md)

---

Всё, что делает панель, — это REST-вызовы под `/api`. Тот же API доступен вашим
собственным инструментам.

**Интерактивная документация** генерируется работающим бэкендом:

| | URL |
| --- | --- |
| Swagger UI | `https://panel.example.com/api/swagger` |
| Схема OpenAPI | `https://panel.example.com/api/openapi` |

Схема OpenAPI авторитетна — эта страница даёт ориентацию.

## Аутентификация

К одним и тем же эндпоинтам приходят два типа учётных данных.

### Сессионные токены

```bash
curl -sX POST https://panel.example.com/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin@example.com","password":"…","code":"123456"}'
```

`code` — TOTP-код, нужен только при включённой 2FA. В ответе приходит токен,
который отправляется с каждым последующим запросом:

```bash
curl https://panel.example.com/api/domains \
  -H "Authorization: Bearer $TOKEN"
```

Сессии живут в таблице `auth_session` и завершаются через `/api/auth/logout`.
Они предназначены для панели; для автоматизации используйте API-ключи.

### API-ключи

Создаются в **Настройки → API-ключи**. Ключ выглядит как `rvx_live_<random>` и
**показывается ровно один раз** — хранятся только BCrypt-хеш и последние четыре
символа, восстановить его нельзя.

```bash
curl https://panel.example.com/api/domains \
  -H "Authorization: Bearer rvx_live_…"
```

Ротируйте любой ключ, который попадал в чат, тикет или скриншот.

### Публичные эндпоинты

Не требуют учётных данных: `/api/auth/login`, `/api/auth/status`, эндпоинты
пикселя и кликов трекинга, `/.well-known/*`. Всё остальное без валидного токена
возвращает `401`.

## Транзакционная отправка

Самый востребованный эндпоинт. Аутентификация по API-ключу:

```bash
curl -sX POST https://panel.example.com/api/send \
  -H "Authorization: Bearer rvx_live_…" \
  -H 'Content-Type: application/json' \
  -d '{
        "from":    "noreply@example.com",
        "to":      "recipient@example.org",
        "subject": "Ваш чек",
        "html":    "<p>Спасибо за заказ.</p>",
        "text":    "Спасибо за заказ."
      }'
```

Передавайте `text` вместе с `html`. Письмо без текстовой альтернативы получает
худшую оценку у любого спам-фильтра, который на это смотрит.

Домен отправителя должен существовать в Ravix и иметь настроенный DKIM, иначе
письмо уйдёт неподписанным — см.
[DNS и доставляемость](dns-deliverability.md). Точные формы запроса и ответа
сверяйте в Swagger UI, прежде чем встраивать это в продакшен.

## Мультитенантность

Ресурсы с аннотацией `@OrgFiltered` скоупятся по организации вызывающего через
`OrgFilterInterceptor`. Супер-админ видит всё. См.
[Мультитенантность](multi-tenant.md).

## Что нужно знать до автоматизации

- **Выборки ограничены, но не полностью постраничны.** `/messages` принимает
  `offset`/`limit` (по умолчанию 50), `/audit` — `limit` (по умолчанию 200,
  максимум 500). `/logs` и `/queue` возвращают ограниченный срез «сначала
  новые», а не курсор — не рассчитывайте обойти всю очередь.
- **`/auth/login` ограничен по частоте.** Пять неудач для одного имени
  пользователя или двадцать с одного IP за пять минут дают блокировку на 15
  минут с ответом `429` и заголовком `Retry-After`. Уважайте этот заголовок,
  а не ретрайте вслепую. Успешный вход сбрасывает счётчик.
- **Для автоматизации используйте API-ключи**, а не вход по паролю: ключи не
  попадают под лимит, потому что не обращаются к `/auth/login`.
- **CORS разрешает same-origin плюс настроенный список.** Если вызываете API из
  браузера с другого origin, добавьте его в `RAVIX_CORS_ORIGINS`; см.
  [Безопасность](security.md).
- **Это пре-релиз 0.1.** Формы эндпоинтов могут меняться между версиями.
  Фиксируйте версию и читайте release notes перед обновлением всего, что
  зависит от API.
